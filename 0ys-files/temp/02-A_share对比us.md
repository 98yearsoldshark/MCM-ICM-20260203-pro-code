## 2. 以赛题A硬口径为标尺：评分点对照矩阵

> 赛题要求强调：
> - 必须是“明确物理/机制推导”的连续时间模型；
> - 数据只能用于参数估计/验证，不能用黑箱拟合替代模型；
> - Q2 要做 TTE、对照、UQ、drivers；
> - Q3 要做假设/参数/波动的敏感性分析。

下表按“对得分最关键”排序：

| 维度（赛题关键点） | `02-A_share`（O奖思路） | 我们方案（MCM_Sim/26A + no7） |
|---|---|---|
| **连续时间机理模型（硬要求）** | 形式上有 ODE，但核心是“SOC差分反推功率 + 回归 + 再回代ODE”，机理约束弱，容易被判为“披着 ODE 的拟合” | **强满足**：电池侧 ECM（OCV/R0/RC）+ 热 + 老化；功耗侧机制化；整体是可解释 ODE/DAE 链 |
| **提前关机/欠压/不可供电边界** | **缺失**：只有 SOC，没有端电压/截止电压/可供电判别式 | **完备**：`V_term<=V_cut`、`Δ<0`（不可供电）等机制 + 关机剩余 SOC 证据 |
| **题面强调的 interplay（协同放大）** | 线性可加为主；缺少网络尾态/后台/弱信号等协同机制 | **强**：RRC 状态机、弱信号惩罚、Poisson 后台唤醒、交互项等可解释协同来源 |
| **不可预测性（同样用法有时更快掉电）** | 缺少随机过程或状态切换解释 | **强**：信号抖动、待机亮屏抖动、后台随机唤醒等随机机制，且能量化波动 |
| **Q2 drivers（最大/最小影响）** | drivers 仅在 S/B/U 的粗变量内解释，且结论易受代理变量偏差影响 | **强**：策略动作 drivers + 机制消融 drivers + 组件消融 drivers；并支持按场景矩阵输出 |
| **Q2 不确定性量化（UQ）** | 有 bootstrap/误差统计，但参数空间/随机机制较弱 | **强**：参数抽样 + 随机过程传播；输出分位数、终止原因概率、UQ宽度排名等 |
| **Q3 敏感性与假设检验** | 在过简模型上做敏感性，结论受限 | **强**：局部敏感性 + PRCC/Spearman 全局敏感性 + 机制消融 + 电池复杂度消融 + SOH 扫描 |

| **开放许可（赛题硬要求）** | 目录中出现外链/引流字样，许可不清晰，不建议写入论文做“正式数据来源” | 更容易做到“可追溯/可复现/可引用”，尤其是公开数据与自建场景 |

## 3. `02-A_share` 的关键硬伤（建议明确摒弃/作为反例）

这些点对“高分口径”是结构性问题，不是调参能救：

1) **缺少端电压/欠压关机机制**  
   真实手机“耗尽”通常是欠压或不可供电先触发，而非 SOC=0；对方模型只能解释“电量百分比下降”，解释不了“突然关机/负载尖峰导致掉电更快”等核心现象。

2) **变量代理不可靠/不可辨识**  
   - `S(t)` 多从电池状态字符串推断“屏幕/活跃”，并不等价于屏幕亮度、显示功耗；  
   - `B(t)` 用蓝牙 detected 推断“蓝牙连接/使用”，也不等价；  
   - `U(t)` 由问卷 `phone_use` 映射而来，往往对同一人近似常数，无法刻画时间变化与场景切换。

3) **缺少题面强调的协同作用与不可预测性来源**  
   线性可加无法解释“弱信号 + 小流量 burst 触发尾态 → 协同放大”这类题面重点。

4) **量级自洽风险**  
   文中一些场景 TTE（如 Idle 上百小时）对应功耗量级偏离常识，容易被评委认为“不可信/不现实”。

5) **复现性问题**  
   代码里 `pid_selected` 与当前数据集不匹配，且 CSV 编码/路径假设不统一，工程上不可直接复用。

## 4. `02-A_share` 的可借鉴之处（建议“写作/对照”层面吸收）

虽然其机理不足，但仍有一些“可吸收为辅助材料”的点：

1) **最低阶 baseline 叙事**  
   可以在论文中用“SOC能量守恒 ODE + 线性可加功耗”作为 Model-0/对照基线，随后指出其缺失（欠压、协同放大、随机波动），从而强化我们升级模型的必要性。

2) **周期切分 + bootstrap 的写法**  
   作为呈现方法可以借鉴，但不要照抄其变量定义与结论。

3) **跨设备参数化的表达方式**  
   适合作为扩展（更像Q4/possible extensions）的一部分写法模板，而非Q3主线。

## 5. 是否值得纳入我们当前 Q2/Q3 的验证与敏感性框架？

结论：**不建议作为主验证数据集；最多作为“附录对照/粗粒度 sanity check”。**

### 5.1 可以做什么（价值有限但可用）

- `battery.csv` 的电量百分比时间序列可用于：
  - 粗估真实世界 `dSOC/dt` 的统计分布与跨人差异；
  - 作为 Q3 中“观测噪声/量化误差（电量是整数%）”的旁证材料；
  - 展示“仅凭电量日志无法辨识 drivers”的论证。

### 5.2 不能做什么（与 Q2/Q3 高分点不匹配）

- 它缺少 CPU/GPU/亮度/吞吐/网络制式/温度等关键变量，无法验证：
  - RRC 尾态、弱信号惩罚、后台唤醒、交互项等机制 drivers；
  - 你们 Q2 的能耗分解结构是否与观测一致；
  - Q3 的“改变假设/参数/波动”对早关机概率、不可供电概率的影响是否可信。

### 5.3 许可问题（赛题硬要求）

赛题明确要求数据“open license/free use”。`02-A_share` 目录出现外链/引流字样且许可不明，**不建议写入论文作为正式数据来源**（内部实验可做，但引用要谨慎）。

## 6. 最终判定：我们是否“完胜”？

以赛题A的评审口径衡量：

- **是的：在关键评分点上，我们方案对 `02-A_share` 是结构性优势，属于“基本完胜”。**
- 但“完胜”不等于“停止优化”：为冲击 Z 奖，建议继续把优势做硬：
  1) 扩充/巩固“许可明确”的公开观测对照（我们已有 AndroWatts；后续可再引入其他开源测量）。  
  2) 把“场景输入如何从可采集变量得到”写得更严谨（让评委相信可落地）。  
  3) 在 Q3 中强化“机制消融 + PRCC + 约束失败统计”的闭环证据链（我们已实现框架，继续提高样本数与图表质量即可）。
