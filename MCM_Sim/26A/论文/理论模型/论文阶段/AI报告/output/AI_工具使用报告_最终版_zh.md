# AI 工具使用报告（按官网要求格式）

> 注：提交前请将团队编号、实际日期/版本等占位符替换为队伍真实记录。

1. **OpenAI Codex（2026-02-02 版本，GPT-5-2）**

   **Query（原样输入）**：  
   将赛题（A 题）拆解为 Q1/Q2/Q3 的“可实现任务清单”，并给出每问应输出的关键图表与指标（例如 TTE、欠压风险、敏感性/不确定性分解），以便我们形成一条清晰的证据链。

   **Output（完整输出）**：  
   - 建议采用统一的连续时间机理框架：以 ODE（SOC 动力学）+ 阈值截止事件为核心，输出以 TTE 与风险指标为主。  
   - 对 Q1：强调“题目重述 + 变量/参数定义 + 场景建模 + 基准预测 + 与数据/常识量级对照”的证据链。  
   - 对 Q2：强调“drivers（主导因素）识别 + 条件对照（one-at-a-time）+ 结论可解释”的图表与对照实验。  
   - 对 Q3：将“参数敏感性、假设敏感性、使用波动敏感性”并列呈现，并为每条主线给出可复现实验与配套图表（PRCC/Tornado、消融/结构对照、分布/方差分解/观测锚定）。  

   **Query（原样输入）**：  
   请为项目设计“可复现且整洁”的工程结构与输出规范：脚本入口、输出目录、paper/study 双模式出图，以及材料目录中“正文最小化、other 留档”的组织方式。

   **Output（完整输出）**：  
   - 建议采用 paper/study 双模式：paper 图只保留论文所需最小信息，study 图补充口径说明与读图提示，便于内部核验。  
   - 建议固定输出目录与命名规则，所有图表与数据表由脚本自动生成，确保可复现与可追溯。  
   - 建议“论文材料目录”结构：每个图对应的子文件夹根目录仅保留 `figure.png` 与 `paper_fragment_zh.md`；其余版本、数据表、英文片段、说明文档统一放入 `other/`，避免覆盖导致难以审计。  

   **Query（原样输入）**：  
   观测锚定的“方差分解 + bootstrap 置信区间”结果看起来过于稳定。请检查可能的实现/统计口径问题，并给出可复现的修复方案（不覆盖旧结果）。

   **Output（完整输出）**：  
   - 提醒常见实现陷阱：若在 resampling 时用布尔 mask/去重索引，会把重复抽样合并，从而人为缩小置信区间。  
   - 建议采用 cluster bootstrap 的加权口径：以“每个簇被抽到的次数”作为权重重算分解占比，并输出新的 v2 结果文件。  
   - 要求保留旧结果用于人工对照与追溯，避免在迭代过程中覆盖历史产物。
