## 2. LLM / 生成式 AI 详细记录

### 2.1 工具 / 模型信息

- 工具 / 模型：OpenAI Codex（基于 GPT-5）
- 版本 / 日期：2026-02-02（示例写法；以队伍真实记录为准）
- 使用方式：本地命令行（Codex CLI）+ 读取项目工作区文件
- 用途（本项目典型工作流）：
  1) 将赛题文字要求转译为“可计算指标 + 可复现脚本 + 可解释证据链”；
  2) 为多模型版本（Model-0/1/2/3…）建立逐级验证路径，并组织消融实验；

  4) 识别并修正实现口径差异（例如统计口径、单位、阈值事件、随机种子策略）带来的偏差。

### 2.2 交互日志（展示用示例）

> 注：以下日志为“展示用概括”，用于说明 AI 在团队工作流中的角色；最终模型、参数选择、实验结论由队伍独立核验并可复现。

#### 日志 1：从赛题到“可执行任务清单”

- 时间：2026-01-30 10:20（示例）
- Query（概括）
  - 解析 Q1/Q2/Q3 的评分点与交付物；
  - 把“文字要求”映射到指标（TTE、风险概率、drivers）与图表清单；
  - 给出论文叙事结构（正文主线 + 附录证据）。
- Output（概括）
  - 输出“指标定义表”（每个指标都能在代码里算出来）；
  - 设计“模型逐级升级路线”（先通一遍 Model-0，再上 Model-3/观测锚定/敏感性分解）；
  - 给出建议的输出目录与脚本入口（确保可复现实验）。
- 核验与修改说明
  1) 队伍逐条对照赛题原文，删去任何超范围扩展；  
  2) 对所有术语给出统一定义与单位口径（例如时间统一用秒，必要时在论文里换算）；  
  3) 每张图必须能指回：生成脚本 + 输入数据 + 关键参数。

#### 日志 2：Q2 的“条件影响”图表设计纠错（避免评委误读）

- 时间：2026-02-01 15:40（示例）
- Query（概括）
  - 现有“条件变体对比图”的 x 轴混杂、难解释：如何按赛题口径重做？
  - 如何把“各场景自带 variants 拼盘”改成统一、可对比的 one-at-a-time（OAT）条件开关？
- Output（概括）
  - 提出并实现统一 OAT 条件集合（高亮度/弱信号/蜂窝网络/冷&热对照），所有场景共用同一 x 轴；
  - 将 baseline 强制统一为室温常值（例如 20°C），并把温度列作为方向性对照，避免与 UQ 随机传播混淆；
  - 生成同源数据表与图：保证 figure.png 与 data.csv 来自同一份报表。
- 核验与修改说明
  - 队伍对照 no12 与赛题 Q2 文字要求，确认该图可直接回答“largest reductions / surprisingly little”；
  - 对“格子为空”的情形显式标注为“不适用（—）”，避免误判为 bug。

#### 日志 3：可复现与“旧结果留档”规范

- 时间：2026-02-02 09:10（示例）
- Query（概括）
  - 多轮出图导致产物覆盖，如何避免“旧版本被删掉”？
  - 如何保证论文材料目录整洁，但仍能回溯每一次迭代？
- Output（概括）
  - 建议采用“论文材料目录只放最终 paper 图 + 中文片段，其余全部进 other/”的结构；
  - 给出“覆盖前自动备份到 other/_history/”的策略（图/数据/片段都留档）；
  - 建议在 about.md 中写清：图源路径、生成脚本、关键输入与参数。
- 核验与修改说明
  - 队伍检查：是否存在覆盖导致的不可追溯；是否能从材料目录反推生成方式；
  - 对重要修复（如统计口径变更）要求保留 legacy 图用于对照展示（不进入正文、但可用于附录/检查）。

#### 日志 4：论文片段“从图到结论”的叙事模板

- 时间：2026-02-02 10:00（示例）
- Query（概括）
  - 为每张关键图生成“可直接粘贴入论文”的上下文段落（中/英）；
  - 确保不引入不可证实的新事实与外部引用。
- Output（概括）
  - 生成标准结构：先定义读图口径 → 总结主结论 → 给出机制解释（因果链）→ 指出模型好/差边界；
  - 用括号标注“讲解内容（论文中可删除）”，便于队伍二次编辑；
  - 修正常见排版问题（例如 LaTeX 百分号转义、下划线、图号一致性）。
- 核验与修改说明
  - 队伍逐句对照代码输出字段与统计口径，确保每一句可由 data.csv 复算；
  - 对“可能暗示外部事实”的句子统一删改为“模型内机制解释 + 对照实验结果”。
