# 回填到配置的建议（从参量估计结果到 src/configs）

目的：把本目录产出的参量估计结果，映射到项目 `MCM_Sim/26A/src/configs/` 中的参数键，便于后续仿真/验证。

建议先阅读：
- `参数估计汇总表.md`（最终数值与来源）
- 各子目录 `about.md`（拟合口径与列来源）

## 1) Model-0（power_params_v0.json）

文件：`MCM_Sim/26A/src/configs/power_params_v0.json`

可直接回填的键：

| 配置键 | 建议值来源 | 说明 |
|---|---|---|
| `screen.P0_W` | `参数估计汇总表` | 屏幕点亮时基准功耗（W） |
| `screen.k_W_per_nit` | `参数估计汇总表` | 亮度线性系数（W/nit） |
| `cpu.k_W` | `参数估计汇总表` | CPU 负载功耗系数（P=k·load） |
| `gpu.k_W` | `参数估计汇总表` | GPU 负载功耗系数（P=k·load） |

注意：Model-0 的 `radio_activity_W`/`background_level_W`/`base_W` 等仍属于场景化假设项，本次参量估计没有强行回填这些键。

## 2) Model-1（power_params_v1_stateful.json）

文件：`MCM_Sim/26A/src/configs/power_params_v1_stateful.json`

可回填的键（建议作为“初值/量级”）：

| 配置键 | 建议值来源 | 说明 |
|---|---|---|
| `screen.P0_W`, `screen.k_W_per_nit` | `参数估计汇总表` | 屏幕亮度项 |
| `cpu.k_W`, `gpu.k_W` | `参数估计汇总表` | 负载功耗项（P=k·load） |
| `rrc.tau_tail_s.wifi` | `参数估计汇总表` | Wi‑Fi 尾态等效时间常数 τ_tail（s） |
| `rrc.e_per_mb_J.wifi` | `参数估计汇总表` | Wi‑Fi 每 MB 能耗（J/MB） |

备注：Model-1 的网络是 RRC 状态机（IDLE/CONNECTED/TAIL）。本次“τ_tail”来自能量守恒反推的**等效**时间常数，
适合用于“量级标定/论文解释”，但若要进一步精细到 `p_state_W` 三态功耗，需要额外的状态时间占比数据或更细粒度 trace。

## 3) no7/Model-2/3（power_params_v2_no7*.json）

文件示例：`MCM_Sim/26A/src/configs/power_params_v2_no7_awcal_mo_v2.json` 等

建议用途：
- 使用 `参数估计汇总表` 的 `e_per_mb_J(wifi)` 与 `tau_tail_s(wifi)` 作为“校验量级/边界”，避免网络项过度乐观或过度悲观。
- 若后续要重新做 AndroWatts 校准/随机搜索，可以把本次估计结果当作**先验/约束**写进调参脚本（而不是手工硬改配置）。

## 4) Model-2 热参数（phone_default_v2_thermal.json）

文件：`MCM_Sim/26A/src/configs/phone_default_v2_thermal.json`

可回填的键（谨慎使用）：

| 配置键 | 建议值来源 | 说明 |
|---|---|---|
| `battery.thermal.R_th_K_per_W` | `参数估计汇总表` | 热阻 R_th（K/W） |
| `battery.thermal.C_th_J_per_K` | `参数估计汇总表` | 热容 C_th（J/K） |

重要说明：
- 本次温度参量来自 AndroWatts 的 `DIFF_SOC_TEMP`（SoC 温度传感器首尾差）反推的一阶模型量级。
- 这更像“SoC/局部温度节点”的短时动态，而不一定等同“电池整体温度”的热惯量。
- 因此建议在仿真中先把它作为“对比实验/敏感性分析”的一个分支，而不是立刻覆盖默认热参数。
