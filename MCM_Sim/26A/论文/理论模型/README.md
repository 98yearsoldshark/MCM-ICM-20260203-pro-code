# 理论模型（面向论文的结构化写作区）

本目录用于把“讨论 → 实现 → 验证 → 成文”全过程结构化沉淀，最终服务于一篇可直接提交的优秀 MCM 论文。

核心原则：**先在代码与实例运行中验证，再写入论文主稿**。避免出现“理论很漂亮但实现/验证对不上”的返工。

## 目录分区与规则（强制）

### 1) `讨论-实现-阶段/`

用途：存放**尚未通过代码实现与实例运行验证**的理论推导、机制讨论、方案草案、待办规划等。

规则（必须遵守）：
- 任何“还没有通过运行实例参数并且通过代码实现”的理论内容，只能写在这里。
- 可以有假设、有分歧、有多方案对比；但要写清楚：
  - 假设/边界条件
  - 计划如何在代码中实现
  - 计划用什么数据/实验去验证

### 2) `论文阶段/`

用途：存放**已经在代码中实现且经验证可靠（高可信）**的内容，作为论文可直接引用的章节草稿与图表说明。

规则（必须遵守）：
- 只有当“算法实现已确定 + 能重复复现结果 + 误差与局限已说明”后，才允许把内容补充到这里。
- 每个章节应配套：
  - 对应的代码路径（例如 `MCM_Sim/26A/src/...`）
  - 可复现实验命令（`PYTHONPATH=... python ...`）
  - 关键结果（表/图/指标）与解释

## 推荐的论文章节结构（建议最终在 `论文阶段/` 下逐步落稿）

你可以按以下章节拆分为多个 Markdown 文件，后续再合并为最终 PDF：

1. `00_摘要与总结.md`
2. `01_问题重述与符号说明.md`
3. `02_模型假设与系统边界.md`
4. `03_模型总体框架（功耗→电池→SOC→TTE）.md`
5. `04_Model-0：能量守恒与基线TTE.md`
6. `05_Model-1：ECM + 截止电压事件（雪崩/不可行域）.md`
7. `06_Model-2：热-电耦合（温度影响）.md`
8. `07_Model-3：老化（容量衰减+内阻增长）.md`
9. `08_参数估计与数据来源（开源/公开）.md`
10. `09_验证、误差分析与局限.md`
11. `10_敏感性与不确定性（UQ）.md`
12. `11_策略建议（用户行为/系统策略）.md`
13. `12_结论与未来工作.md`
14. `附录_复现指南与代码清单.md`
15. `附录_AI使用报告.md`（按 COMAP 要求）

## 文件命名建议

- 建议用编号前缀保持顺序：`00_...`、`01_...`。
- 建议每个文件开头写“当前可信级别”：
  - `阶段：讨论-实现` 或 `阶段：论文阶段`
  - `状态：待实现/已实现/已验证`
