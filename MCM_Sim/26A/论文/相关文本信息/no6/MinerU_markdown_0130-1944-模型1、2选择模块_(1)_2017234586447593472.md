# Step 1 物理过程抽象（Physical Abstraction）

• 输入：题面描述（锂电池、不可预测耗尽、影响因素：屏幕/CPU/网络/后台/温度等）、你选定的 5 个使用场景（S1–S5）。

• 动作 1：确定电池本体物理定律：电荷守恒（SOC）、能量守恒/功率守恒（P=VI）、焦耳热（I^2R）、牛顿冷却（hA(T−Tamb)）。

• 动作2：确定系统层抽象：设备为恒功率负载（CPL）；子系统（屏幕/CPU/DVFS/网络RRC/GPS/后台）以“状态驱动 $^ +$ 交互修正”生成 P_device(t)。

• 动作 3：确定终止机制：欠压截止 V_term≤V_cut、SOC≤SOC_min、以及 CPL 可行性判别$\Delta { < } 0$ （雪崩）。

• 输出物：

• • 模型框架图（SOC–T–电压/功率耦合 $^ +$ 状态机功耗层）。

• • 变量列表（状态、输入、参数、输出）。

• • 终止条件定义（TTE 首次到达时间）。

【决策点 D1：是否需要加入极化 RC？】

• 判断依据：若场景存在频繁负载突变（S2社交/浏览、弱信号蜂窝突发、解锁/刷视频等），电压存在滞后/回弹现象，则“需要”。

• 是 采用扩展电池电学： ${ \mathsf { O C V } } + { \mathsf { R O } } +$ 一阶 RC 极化（V_p）。

• 否 采用简化电学： $\mathsf { O C V } + \mathsf { R O }$ （保分核心）。

# Step 3 模型构建（Model Construction）

• 输入：参数表 $^ +$ 场景输入 u_s(t) + 选择的电学复杂度（含/不含 RC）。

• 动作 1：写出状态方程：SOC 动力学、温度动力学、（可选）极化动态。

• 动作 2：写出电学耦合：V_term=V_OCV−IR0−V_p；功率守恒 P_load=V_term·I；得到 I 的二次方程与判别式 Δ。

• 动作 3：写出功耗生成：P_device=ΣP_k + P_int（交互项）；再由 η_PMIC 得到 P_load。

• 输出物：

• • 完整方程组（ODE $^ +$ 代数约束/二次方程）。

• • 数值求解模块设计（power_model / current_solver / ode_rhs / event_fn）。

• • 可运行的仿真框架（Matlab ode45 + events）。

【决策点 D3：是否出现数值不稳定或无实根频繁？】

• 若 $\Delta { < } 0$ 频繁且与直觉不符：可能是 R0/OCV 范围不合理、P_load 过大、η_PMIC 太小或交互项过强。

• 处理：缩小功耗系数范围、增加散热(hA)、加入DVFS（高温限功耗）、或改用分段时间步长。

# Step 4 数据校准（Calibration / Identification）

• 输入：可采集数据或文献量级（SOC%、温度、亮屏时长、吞吐、网络类型）、以及你设定的场景基准。

• 动作 2：场景校准：用 S3（视频）校准屏幕系数 k_panel 与网络吞吐系数 k_bit；用S4（游戏）校准 α_big 与热反馈参数（T_th, κ）。

• 动作 3：欠压校准：调整 R_ref、低 SOC 增阻参数(A,B)与 V_OCV 低 SOC 段，使欠压提前关机现象在低温/重载时出现且概率合理。

• 输出物：

• • 校准后的参数集 $\boldsymbol { \Theta ^ { * } }$ 。

• • 校准拟合图：预测 vs 观测（SOC 曲线/温度曲线/TTE）。

• • 参数置信区间或后验分布（用于不确定性传播）。

【决策点 D4：校准后是否出现物理违背？】

• 例如：V_OCV 非单调、R_int<0、η_PMIC>1、SOC 出现反向增长（放电期）。

• 若出现 回到 Step2 调整参数化形式/约束（加单调约束、截断分布、罚函数）。

# Step 5 结果验证与鲁棒性（Validation & Robustness）

# （2）状态机定义（z(t)）：把协同作用“机制化”

• 屏幕 z_s(t)：OFF↔ON；由解锁/抬起/超时触发；输入为 ScreenOn(t)、B(t)。

• CPU/DVFS：用 u_eff(t)=u_des(t)·g(T(t)) 表示温度反馈限频（T↑ 算力上限 $\downarrow $ 任务持续时间↑）。

DVFS 是 Dynamic Voltage and Frequency Scaling（动态电压与频率调节）。

手机/电脑的 CPU、GPU 会根据“当前负载 $^ +$ 温度 $^ +$ 省电策略”，动态改变工作频率 f 和 供电电压 V ，从而控制性能、功耗和发热。

• 网络 RRC z_n(t)：{IDLE, CONNECTED, TAIL}；数据到达 CONNECTED；传输结束 TAIL（维持 τ_tail）；计时结束 IDLE。

• GPS z_g(t)：OFF/ON；输入 δ_gps(t) 与 f_gps(t)。

• 后台：用 ρ(t)（占空比）或唤醒事件触发 CPU/网络短时活跃（常导致 RRC 进入CONNECTED/TAIL） 。

# （3）从状态机到功耗（P_device）：主干+交互项（避免“简单叠加”漏洞）

主干结构：P_device(t)=P_base+P_screen+P_cpu+P_net+P_gps+P_bg+P_int。

• 屏幕：P_screen=z_s·(P_driver+k_panel·A_size·B)。

• CPU：P_cpu= P_idle $^ +$ f(u_eff)；可加门控：屏幕 OFF 时活跃项乘 α_s≤1。

• 网络：P_net=P_state(z_n,Type)+k_bit(Type)·D·ψ(Signal)，其中 $\psi$ 为弱信号惩罚，P_state在 TAIL 仍显著（尾能量）。

• GPS：P_gps=z_g·(P_gps0+k_gps·f_gps)。

• 后台：P_bg=ρ·P_wake 或 P_bg=λ·E_wake（泊松唤醒）。

• 交互项（协同作用最低成本表达）：P_int=β1·(z_s·I[z_n≠IDLE]) + β2·(I[z_n≠IDLE]·I[u_eff>θ])+ β3·(z_s·I[u_eff>θ])。

# 3.6 模型好/差的边界（题面必答）

表现好：负载平稳、状态切换少（S1 待机、S3 流媒体稳定下行）。

可能偏差大：

• S4 游戏：热限频强、功耗受系统调度影响大；需要 DVFS 闭环，否则会低估“越热越费电”。

• 弱信号蜂窝：RRC 尾能量 $+$ 功放功耗波动大；需要 RRC 状态机与 signal 惩罚项。

• 频繁切换：若没有 RC 极化，会低估欠压提前关机与“回弹”现象

# 四、可直接替换进论文的“ ” 精炼模型表述 （建议放在 Model Section 开头）

We model a smartphone as a multi-physics hybrid dynamical system. The battery state evolvescontinuously according to charge conservation and thermodynamics, while major subsystems(screen, CPU/DVFS, cellular/WiFi RRC, GPS, background wakeups) evolve as coupled finite-statemachines that generate the device power demand. The battery is represented by an OCVsource, a nonlinear ohmic resistance, and a first-order polarization branch, allowing voltagehysteresis and rebound under abrupt load changes. Time-to-empty is defined as the first hittingtime of SOC depletion, undervoltage cutoff, or infeasible power delivery (discriminant $< 0$ ).
