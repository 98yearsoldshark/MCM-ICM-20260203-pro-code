# Load-Model（负载-电池模型相关资料）

本目录面向 2026 MCM Problem A（Modeling Smartphone Battery Drain），用于整理“**负载/工况输入** → **电池连续时间模型** → **SOC(t)/TTE 输出**”这条链路中最容易复用、也最容易写进论文的模块与资料包：
- **ECM（1RC/2RC Thevenin）**：连续时间 ODE，可解释电压动态与“截止电压触发关机”
- **EKF（扩展卡尔曼滤波）**：用观测电压/电流估计 SOC，并显式量化不确定性（加分项）
- **Battery Historian（Android bugreport）**：从真实手机事件时间线抽取“屏幕/网络/定位/唤醒锁”等工况，构造 `P(t)`/`I(t)` 输入与证据链

如果你只想快速对齐题意：优先用 `ECM-1RCor2RC/` 做电池层主模型；有数据就加 `EKF/` 做参数与不确定性；用 `Battery-Historian/` 把“使用行为”变成可解释的输入函数。

## 1. 赛题 A 合规性对照（你需要满足什么）

赛题原文位置：`MCM_Sim/26A/论文/赛题/A英文纯文本.md`

题目硬性门槛可以总结为：
- **连续时间**（continuous-time）模型：必须给出 ODE（或 ODE 系统）并输出 `SOC(t)`
- **机理明确**：不能只做离散拟合/黑盒回归
- **TTE**：需要计算/近似 time-to-empty，并解释导致快速耗电的驱动因素
- **敏感性/假设**：改变参数、假设或用电波动，检查预测变化
- **建议**：把模型洞察翻译成用户/系统层面的可执行建议
- **数据合规**：数据只能作为支撑（参数估计/验证），并且应可追溯、公开可得、满足开放许可

本目录子模块如何对齐：
- `ECM-1RCor2RC/`：直接满足“连续时间 + 机理 + SOC/TTE”的核心要求（建议作为论文主模型电池层）
- `EKF/`：对齐“参数要有依据、量化不确定性、验证模型是否可信”（非硬性要求，但非常适合写进论文的方法部分）
- `Battery-Historian/`：对齐“数据作为支撑（非替代）”，用于构造/验证负载输入，并提供开放样例与追溯文件

对应的“写论文用上下文”入口：
- ECM：`MCM_Sim/26A/Load-Model/ECM-1RCor2RC/MCM26A_PROBLEM_CONTEXT.md`
- EKF：`MCM_Sim/26A/Load-Model/EKF/MCM26A_PROBLEM_CONTEXT.md`
- Battery Historian：`MCM_Sim/26A/Load-Model/Battery-Historian/赛题A_用途说明.md`

## 3. 推荐工作流（从题目到可写论文的最短闭环）

下面是一条“对齐题意 + 可复现 + 便于写作”的工作流，建议先跑通再扩展：

### Step 0：统一符号、单位、边界条件

建议先全队统一这些约定（写代码与写论文都省事）：
- 电流符号：本目录默认 **放电 `I>0`**，SOC 随时间下降
- 容量单位：`Q` 用 Ah；在 ODE 里出现 `3600*Q`（把 Ah 转成库仑）
- 终止条件：至少包含电压截止 `V <= V_cut`（贴近手机“关机”）

### Step 1：把“使用行为”抽象成连续时间输入（解释性建模）

题目建议把屏幕、处理器、网络、GPS、后台任务等纳入模型。推荐做法是构造可解释的功耗分解：

`P(t) = P_base + P_screen(s(t)) + P_cpu(c(t)) + P_net(n(t)) + P_gps(g(t)) + ...`

其中 `s(t), c(t), n(t), g(t)` 可以是分段常数（开/关、强/弱）或连续近似的强度量。

数据来源建议：
- 能采集就采集（注意隐私/脱敏/许可）
- 想先跑通流程：用 `Battery-Historian/` 的公开样例做“工况提取示例”，在论文里作为“证据链/方法示例”

### Step 2：电池连续时间模型（ECM）输出 `SOC(t)` 与 `V(t)`

用 `ECM-1RCor2RC/` 给出连续时间 ODE（示例，2RC）：
- `dSOC/dt = - I / (3600*Q)`
- `dVj/dt = -Vj/(Rj*Cj) + I/Cj`，`j=1,2`
- `V = OCV(SOC) - I*R0 - V1 - V2`

做法建议：
- 论文推导：使用“电流输入”的教科书形式（更清晰）
- 工程实现：若你的上游是功耗 `P(t)`，可把 `P(t)` 转成 `I(t)` 或做“功率闭合”（见 26A 主代码）

### Step 3：用“截止电压事件”定义 TTE（Time-to-Empty）

TTE 的推荐定义（可写进论文）：
- `TTE = inf{ t | V(t) <= V_cut }`

用这个定义，你们就能解释题目要求的现象：
- 同样的 SOC，不同负载历史/强度会导致端电压不同
- 高负载、低温、老化（等效为参数变化）会让电压更早触发截止，因此 TTE 不线性

### Step 4：参数估计/验证与不确定性（建议选做）

如果你能拿到观测 `V(t)`（以及 `I(t)` 或 `P(t)`），可用 `EKF/` 来：
- 验证 ECM 参数与 `OCV(SOC)` 是否“解释得通”电压动态
- 用过程噪声/测量噪声与协方差传播，对 SOC/TTE 给出置信区间或误差带

这一步对齐题目里“参数要有依据、量化不确定性”的要求，并且通常比“纯回归”更合规、更好写。

### Step 5：敏感性分析与建议输出

建议围绕这些“可解释且可操作”的量做敏感性：
- `Q`（有效容量：老化/温度影响可等效到这里）
- `R0`、`RjCj`（内阻/极化动力学：影响电压下跌与截止触发）
- `V_cut`（系统阈值：对 TTE 的影响很直观）
- `P(t)` 的组成（屏幕/网络/后台等占比）

然后把结论翻译成建议（用户侧/系统侧），例如降低亮度、限制后台唤醒、切换网络模式、限制高峰功耗等。

## 5. 常见坑（写代码/写论文都会踩）

- 电流符号不统一：SOC 会“越放电越上升”（最常见）
- Ah/mAh 搞混：量纲对了但数量级差 1000 倍
- `OCV(SOC)` 过于平坦：SOC 从电压中不可观测，EKF 很难纠正初值
- 只做拟合不写机理：容易直接不合规（题目明确反对离散拟合/黑盒替代连续模型）
- 数据许可不清晰：题目要求数据“freely available + open license”，记得在参考文献与附录写清楚来源/许可/用途
