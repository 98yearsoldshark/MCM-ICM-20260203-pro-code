# 面向 2026 MCM A（智能手机耗电建模）：本目录的作用与使用建议

对应赛题位置：`MCM_Sim/26A/论文/赛题/`（问题 A：Modeling Smartphone Battery Drain）。

本赛题要求建立**连续时间**的 SOC（State of Charge）模型，并强调“**数据作为支撑，而非替代**”。Battery Historian 提供的 bugreport/事件时间线，适合作为你连续时间模型里“负载项/工况项”的依据与校验材料：用来解释为什么同样电量下，不同使用行为会导致不同的耗尽时间（TTE）。

## 1. 本目录能为赛题 A 提供什么

- **可复现实验输入**：`raw/bugreport_*.txt` 为可直接上传/解析的 bugreport 样例，便于你快速跑通“解析 -> 提取特征 -> 建模”的流程。
- **“工况”证据链**：bugreport 中包含的屏幕/网络/定位/唤醒锁等事件时间线，可用于构造你的模型输入函数（例如开关型的 `u(t)`、分段常数的负载、或连续近似的负载强度）。
- **参数估计/合理性校验**：可用样例数据做量纲检查、数量级检查、敏感性分析示例；也可用你自己采集的 bugreport 进行参数估计与验证（注意隐私与授权）。
- **开放数据合规**：赛题要求数据“可自由获取且开放许可”。本目录样例来源与追溯文件见 `sources/` 与 `download_list.md`。

## 2. 你可以从 bugreport 里提取哪些建模要素（示例）

不同 Android 版本字段会有差异，但通常可以抽象成几类“可驱动功耗变化”的状态/事件：

- **SOC 或电量指示的变化**：电量百分比、电池电压、温度（如有）等。
- **屏幕相关**：亮屏/熄屏、亮度水平、屏幕使用时长。
- **处理器/唤醒相关**：CPU 活动窗口、wakelock（保持唤醒的锁）、后台任务导致的“看似空闲但不睡眠”。
- **网络相关**：Wi-Fi / 蜂窝数据连接状态变化、信号强弱、数据传输活跃窗口。
- **定位相关**：GPS 相关传感器/请求活动窗口。

这些信息非常适合用于“解释性建模”：把功耗拆成若干可解释的组件，并在时间上叠加。

## 3. 如何把这些信息落到连续时间模型里（推荐写法）

赛题核心是连续时间模型。一个常见写法是从能量或 SOC 的微分方程出发：

- 以 SOC 为状态：
  - `dSOC/dt = - I(t) / C_eff`
- 或以电池能量为状态：
  - `dE/dt = - P(t)`

其中 `I(t)` 或 `P(t)` 可以拆成“基线 + 各模块贡献”的形式，例如：

- `P(t) = P_base + P_screen(s(t)) + P_cpu(c(t)) + P_net(n(t)) + P_gps(g(t)) + ...`

这里的 `s(t), c(t), n(t), g(t)` 就来自 bugreport 的事件/状态：你可以把它们建成分段常数输入（开/关、强/弱），再在连续时间模型中驱动 SOC 演化。这样既满足“连续时间”，又能保留可解释性，并便于做敏感性分析与提出节能建议。

## 4. 使用样例数据的边界与注意事项

- 本目录样例文件名中的 `KK`/`L` 分别对应较老的 Android 版本（KitKat / Lollipop）。它们更适合用于**流程验证**与**解析健壮性**，不建议直接当作“现代手机”的参数真值来源。
- bugreport 可能包含敏感信息。若你采集自己的 bugreport：在对外共享/提交前务必脱敏，并确保满足赛题“开放许可/可公开获取”的要求。

## 5. 推荐工作流（最小闭环）

1. 用 `raw/` 的样例 bugreport 跑通解析与特征提取（先保证可复现）。
2. 选定你的连续时间状态方程（SOC 或能量），定义各用电模块的输入项。
3. 用数据做参数估计/数量级校验 + 不确定性与敏感性分析。
4. 设计场景（降低亮度、关 GPS、切换网络模式等）并输出 TTE 与建议。
